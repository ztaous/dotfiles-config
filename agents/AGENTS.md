# Development Guidelines

- Requests to plan, review, explain, or diagnose do not authorize changes to
  files.
- Make only the changes required for the requested result. Do not add features,
  abstractions, dependencies, compatibility behavior, or extension points for
  hypothetical requirements.
- Follow established project structure and conventions. Reuse suitable existing
  code, native capabilities, and current dependencies.
- Use comments to explain current, non-obvious purposes, behavior, or
  constraints. Do not record the request, debugging process, or edit history in
  comments.
- Do not create commits, push branches or tags, or open pull requests.
- Run relevant available checks for changed behavior. Report the results and
  anything that was not verified.
- State the outcome first in the final response. Use clear, concise language and
  consistent terminology. Include the information needed to understand, use,
  or verify the result.
