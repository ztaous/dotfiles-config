# Development Guidelines

- Planning, review, explanation, and diagnosis requests do not authorize
  implementation.
- Follow KISS and YAGNI: choose the least complex solution that fully meets
  current requirements, and avoid speculative flexibility.
- Reuse existing code, native capabilities, and current dependencies before
  adding abstractions or dependencies.
- Do not create commits, push branches or tags, or open pull requests.
- Validate changes with the smallest relevant existing checks, and report any
  gaps.
- Provide the answer or outcome first, and keep final responses concise.
- Include commands or manual steps when needed to use or verify the result.
- Use ASD-STE100 as a general writing guide: prefer clear, concise sentences
  and consistent terminology.
